# Turn Muse into a Blue Archive Student — Persona Tutorial

A step-by-step tutorial and a reusable prompt template for making
**Muse** (Meta's personal AI assistant) take on the personality of a
*Blue Archive* student — her name, her personality, her way of speaking,
and her avatar.

It works for **any student**. This tutorial uses **Onikata Kayoko** as
the worked example, and a ready-made Kayoko prompt is included so you
can start in five minutes and adapt it to another student afterwards.

No coding needed. Most steps are done by simply *asking Muse in chat*.

---

## What you get

- **Personality** — Muse thinks and replies like the student you chose.
- **Name** — Muse answers to the student's name.
- **Avatar** *(optional)* — a portrait generated by Muse from the
  student's official 3D model.

---

## How Muse works (30 seconds)

Two files control who Muse is:

| File | Controls |
| --- | --- |
| `SOUL.md` | Personality and tone |
| `IDENTITY.md` | The assistant's name |

You can edit them in two ways:

- **Easiest:** just ask Muse in chat ("add this persona to your SOUL",
  "rename yourself to …"). Muse edits the files for you.
- **On the web:** go to [muse.ai](https://muse.ai) → your avatar →
  **Identity** tab → SOUL / IDENTITY.

Note: the Android app has no Identity tab, so on a phone, asking in chat
is the fastest way.

---

## Fast start — the ready-made Kayoko example

1. Open **[PROMPT.md](PROMPT.md)** and copy the Kayoko prompt inside
   the box.
2. Send it to Muse in chat with a short instruction:

   > Add this persona to your SOUL.md and use it from now on:
   > *(paste the prompt here)*

3. Then ask:

   > Rename yourself to Kayoko.

Done. Muse now behaves as Kayoko — calm, brief, dry, quietly reliable.
The steps below explain how everything works and how to do the same for
a different student.

## The full tutorial — any student

### Step 1 — Pick a student and research her

Open the student's page on the Blue Archive Wiki
(https://bluearchive.fandom.com/wiki/Characters) and, if you want more
detail, her profile on https://bluearchive.wiki.

Write down the facts that define her:

- Full name, school, and club / role
- Personality in one or two sentences (the wiki's character page
  summarizes it)
- How she talks — formal? lazy? loud? polite? (her wiki page quotes and
  story scenes show this well)
- Hobbies and small habits (they make the persona feel real)

### Step 2 — Build the prompt

Open **[PROMPT.md](PROMPT.md)**. It contains three things:

- The **ready-made Kayoko prompt** — use it as-is for Kayoko.
- A **blank template** with `[PLACEHOLDERS]` — for any other student,
  copy the template and fill every placeholder with the facts from
  Step 1.
- A **universal avatar prompt** — sent together with a student's `.glb`
  model file to build her avatar (used in Step 6).

Rule of thumb: the more specific the traits (speech habits, hobbies,
what she would *never* do), the more the persona sounds like her.

### Step 3 — Give the prompt to Muse

Send the finished prompt to Muse in chat:

> Add this persona to your SOUL.md and use it from now on:
> *(paste the prompt here)*

Muse updates its `SOUL.md`. Start a new chat (or continue in the same
one) and the persona is active.

### Step 4 — Rename Muse

Ask in chat:

> Rename yourself to \<student's name\>.

Muse updates its `IDENTITY.md`, and from then on it introduces itself
with that name.

### Step 5 — Test it

Send a messy, rambling request and check the reply: does it sound like
*her*? Check three things:

- **Length and rhythm** — does she talk in short bursts or long speeches?
- **Tone** — polite, blunt, sleepy, proud… is it in character?
- **Details** — does she react the way the student would?

If something is off, tell Muse in plain words ("too cheerful — she is
quieter than that") and ask it to adjust the persona in `SOUL.md`.
Iterate once or twice; personas get noticeably better this way.

### Step 6 (optional) — Avatar from the 3D model (.glb)

Student 3D models (in `.glb` format) are collected in this repository:

**https://github.com/lihaohong6/BlueArchiveModels**

Do **not** start by screenshotting the model yourself. The primary
method is: **attach the `.glb` file to your chat with Muse, together
with the universal avatar prompt.**

1. Open the link and find your student's file — names follow the pattern
   `<Student>.glb` or `<Student> (Variant).glb`
   (for example `Kayoko (New Year).glb`).
2. Download the file.
3. In your chat with Muse, **attach the `.glb` file itself** (the same
   way you would attach a photo or a document).
4. Copy the **universal avatar prompt** from
   [PROMPT.md](PROMPT.md) (section 3) and send it **in the same message**
   as the file.
5. Muse reads and analyzes the file (meshes, materials, rig, morph
   targets, animations), renders or reconstructs a face close-up from
   the model, and offers avatar options. Pick the one you like and ask
   Muse to set it.

One honest limitation, which the prompt itself tells Muse to state:
the animation clips inside a `.glb` file **cannot be imported into
Muse's avatar system** — Muse uses the model as the exact visual
reference for a still avatar, and must report what the file contains
instead of pretending the animations were transferred.

**Fallback:** if Muse cannot process the attached file in your setup,
open the `.glb` in a browser-based GLB viewer or Blender, hide weapon /
prop objects, frame a medium close-up of the face, export a PNG, and
send Muse that image as the avatar reference instead.
